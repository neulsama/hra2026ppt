# 콘티·애니메이션 작업 지침

이 발표 슬라이드의 애니메이션을 만들거나 고칠 때 따르는 절차다. 사람이든 Claude Code든 이 문서대로 작업한다. 2페이지 부엉이 컷(`작업지침/콘티/P02_입학축하_부엉이와_양피지_견본.md`)이 이 절차로 만든 첫 결과물이고, 사용자가 마음에 든다고 확인했다.

이 저장소의 공통 규칙(`CLAUDE.md`, `.claude/skills/hra-ppt-qa/SKILL.md`)이 먼저다. 이 문서는 그 위에 애니메이션 작업에 필요한 것을 더한다.

## 1. 사용자가 정한 원칙

대화에서 사용자가 직접 말한 것이다. 원문은 `작업지침/콘티/00_요청원문_모음.md`에 있다.

1. **한 컷씩 한다.** 콘티 하나를 쓰고, 그 컷의 사이트 애니메이션을 고치고, 바로 배포한 뒤 다음 컷 콘티로 넘어간다. 여러 컷을 한꺼번에 고치지 않는다.
2. **콘티는 실제 영화처럼 길고 상세하게** 쓴다. 샷마다 화면 설명, 카메라, 움직임, 시간이 있어야 한다.
3. **영화 기법을 인터넷에서 찾아 근거로 단다.** 부드러운 애니메이션이 목표다.
4. **실사 그림을 쓴다.** 부엉이, 나무상자 같은 것은 만화풍 SVG로 그리지 않는다. 사용자가 준 사진·AI 그림을 오려서 쓴다. 사용자가 준 그림은 공개 사용 허락을 받은 자료다.
5. **"자동"의 뜻은 PPT와 같다.** 화면 안에 "봉인 열기" 같은 별도 버튼을 두지 않는다. 장에 들어오면 시작할 연출은 저절로 시작한다. 사회자가 다음(→, PageDown, 클리커)을 누르면, 그 장에 남은 연출이 있을 때는 다음 장으로 넘어가지 않고 그 연출을 한다. 남은 것이 없을 때 다음 장으로 간다.
6. **매 컷 작업 뒤 바로 커밋하고 배포한다.** 원본을 지켜야 할 때는 새 브랜치를 만든다.
7. **사용자가 말하지 않은 화면 문구나 새 요소를 지어 넣지 않는다.** 더 좋을 것 같은 것은 "제안(확인 필요)"으로 따로 묻는다.

## 3. 컷 이름과 파일

- 콘티 파일: `작업지침/콘티/P{페이지 번호 두 자리}_{장면 이름}.md` (예: `P11_타임캡슐.md`). 페이지 번호는 화면 왼쪽 아래 번호(1부터)다. `stage.js`의 `slides` 배열 번호(0부터)와 1 차이가 난다. 콘티 첫 표에 둘 다 적는다.
- 에셋 폴더: `assets/cuts/P{번호}/`. 2페이지만 예전 이름 그대로 `assets/cuts/C02/`다.
- 연출 코드: `effects/{이름}.js`, `effects/{이름}.css`. `index.html`에 `stage.js`보다 먼저 불러온다.

## 5. 실사 에셋 만들기

### 도구
Python 가상환경에 `pillow numpy opencv-python-headless "rembg[cpu]"`. rembg의 `isnet-general-use` 모델(약 180MB)은 처음 한 번 받는다.

### 부엉이 컷에서 통한 방법
1. **원본은 가장 큰 것을 쓴다.** 사용자가 `assets/reference/`(또는 `qa/refs/`)에 넣은 원본을 쓴다. 832px짜리보다 1130px짜리가 훨씬 선명했다.
2. **배경 제거는 두 가지를 합친다.** rembg는 몸통·물건은 잘 따지만, 어두운 배경 위의 밝은 날개는 반쯤 지운다. 그래서 "배경보다 밝은 부분" 마스크를 따로 만들어 둘 중 큰 값을 쓴다. 눈송이 같은 작은 점은 연결 영역 크기로 걸러낸다.
3. **원본 가장자리에서 잘린 부분은 흐린다.** 날개 끝이 그림 위·오른쪽 가장자리에서 잘려 있었다. 60~70px에 걸쳐 투명도를 0으로 내려 깃털 끝처럼 보이게 한다. 안 하면 일자 선이 보인다.
4. **움직일 부위는 레이어로 나눈다.** 다각형으로 날개 셋 + 몸통을 나누고, 모든 레이어를 같은 크기의 캔버스(1200×744)에 둔다. 그러면 CSS에서 같은 상자에 겹치기만 하면 된다. 축(어깨)은 그 캔버스 기준 %로 적는다.
5. **움직이는 부위의 뿌리는 몸통이 덮게 한다.** 날개 레이어를 몸통 뒤에 두면 회전해도 이음매가 몸통에 가려진다.
6. **필요 없는 소품은 지운다.** 원본의 봉투를 다각형으로 지우되, 발톱(채도가 낮거나 어두운 픽셀)은 남겼다. 지운 뒤 작은 부스러기를 다시 정리한다.
7. **결과는 초록색 배경에 얹어 직접 본다.** 날개를 각도별로 돌린 미리보기도 만든다.

### 그림 안의 물건을 움직일 때 (예: 1페이지 배)
물건을 오려 낸 뒤, 원래 자리는 OpenCV inpaint로 메우고 조금 어둡게 눌러 둔다(배경판). 그 위에 오린 물건을 얹어 움직인다. 크게 움직이면 메운 자리가 보이니 움직임 폭을 작게 한다.

### 종이·질감
초대장 사이트(hra26yep.vercel.app)의 그림을 먼저 찾는다. 예를 들어 양피지는 `/art/academy-folio.webp`(글씨 없는 원본)를 썼다. 스크린샷에서 글씨를 지우는 것보다 훨씬 깨끗하다.

## 6. 구현 규칙

- **움직이는 속성:** `transform` 계열(`translate`, `rotate`, `scale`)과 `opacity`만. `top/left/width/height`는 움직이지 않는다. 종이가 펼쳐지는 것은 `clip-path: inset()`과 원통의 `translate`를 같은 곡선으로 맞춘다.
- **상태는 클래스로:** 들어옴(`*-arriving`) → 머무름(`*-hovering`/`*-open`) → 나감(`*-rolling`, `*-departing`). 타이머는 JS에서 걸고, 슬라이드를 떠날 때 정리 함수에서 지운다.
- **PPT식 다음 버튼:** 연출 객체에 `pending()`(남은 연출이 있으면 true)과 `cue()`(그것을 실행)를 둔다. `stage.js`의 `go()`와 `runCue()`가 다음 장으로 가기 전에 `pending()`을 먼저 본다. 2페이지 연결 코드(`owlEffect`, `owlApi`)가 견본이다. 연출 중에 다음을 누르면 끝 상태로 건너뛰는 것이 기본이다.
- **기본 스타일은 끝 상태:** 움직임 줄이기 모드(`prefers-reduced-motion`)에서는 애니메이션이 모두 꺼진다. 그래서 CSS의 기본값은 마지막 모습이고, 애니메이션은 `from`을 써서 거기까지 가게 만든다.
- **이름 충돌 조심:** `@keyframes` 이름과 클래스 이름이 `stage.css`와 겹치지 않는지 `grep`으로 먼저 본다. 이름을 바꿀 때는 `sed`로 일괄 치환하지 말고 정확한 자리만 바꾼다(부엉이 작업 때 `owl-depart`를 바꾸다 `owl-departing`까지 바뀐 일이 있었다).
- **위치의 기준:** `transform`이 걸린 요소(예: 등장 애니메이션이 있는 `.scene-body`) 안에 `position:absolute`를 넣으면 기준이 그 요소가 된다. 화면 기준으로 놓을 것은 슬라이드(`#slide`)에 직접 붙인다.
- **이징 이름표:** `00_기법_사전.md` 8절(부드러운 정지, 무거운 출발, 오가는 흔들림, 튀어 오름, 기계적)을 쓴다.
- **글자 크기:** `cqw` 단위. 60pt = 1920×1080에서 80px = 4.17cqw.

## 7. 검증

1. **연속 사진:** 실제 시간으로 찍는다. headless Chrome의 `--virtual-time-budget` 캡처는 애니메이션 중간이 제멋대로 찍히므로 믿지 않는다. Playwright나 DevTools 프로토콜로 0.1~0.5초 간격 스크린샷을 찍어 한 장으로 묶어 본다. 이 저장소에서는 `qa.py motion`, `qa.py shot`을 쓴다.
2. **콘티와 대조:** 콘티 11절의 시각마다 화면이 콘티 설명과 같은지 본다.
3. **다음 버튼:** 연출 중간에 다음 → 끝으로 건너뛰는지. 끝난 뒤 다음 → 나가는 연출 뒤 다음 장으로 가는지. **다음을 연달아 두 번 누르면** 나가는 연출을 건너뛰고 넘어갈 수 있으니, 시험할 때는 한 번만 누른다.
4. **움직임 줄이기 모드:** 끝 모습이 정지 화면으로 맞게 보이는지
5. **다른 장:** `qa.py baseline`. 의도한 장만 `baseline --update --slides N`
6. **콘솔 오류 0**
7. **배포 후:** Pages 주소에서 한 번 더 열어 본다. 배포에는 1~2분 걸리고, 새 그림 파일은 조금 더 늦게 뜰 수 있다.

## 8. 커밋과 배포

- 컷 하나가 끝날 때마다 커밋하고 푸시한다. 커밋 메시지 첫 줄: `P{번호} {장면}: 무엇을 바꿨는지`
- 원본을 남겨야 하면 새 브랜치에서 작업한다. 지금 작업 브랜치는 `owl-cut`이다.
- GitHub Pages는 설정에서 고른 브랜치 하나만 배포한다(Settings → Pages). 다른 브랜치에서 작업했으면 그 브랜치를 Pages에 연결하거나 배포 브랜치에 합쳐야 사이트에 나온다.

## 9. 부엉이 컷에서 배운 것

- 사용자는 "가져온 다음 열린다"처럼 **순서와 인과**를 중요하게 본다. 물건이 처음부터 화면에 놓여 있으면 안 되고, 누가 가져오는지 보여야 한다.
- "가볍게"라고 하면 정말 작게 한다. 날갯짓은 어깨 축 14° 안쪽, 0.8~1.1초 주기면 충분했다. 실제 부엉이는 날갯짓이 느리고 날개 안 움직임이 적다.
- 글씨는 "드러나기만" 한다. 빛나기, 서서히 나타나기, 저절로 써지기를 넣지 않는다(사용자가 명시적으로 금지).
- 원본 그림의 한계(날개 하나의 자세뿐, 부리로 무는 동작 불가)는 숨기지 말고 콘티에 적고 대안을 묻는다. 사용자는 "발로 쥐고 날아가는 것 좋다"처럼 빨리 정해 준다.
